# Architecture

## 分层原则

项目将界面、业务规则、状态和 Three.js 运行时拆开，避免把编辑器交互直接写进渲染层。

| 目录 | 职责 |
| --- | --- |
| `src/app` | 应用入口、整体布局、错误边界和全局样式。 |
| `src/components` | 可视界面与交互：资产列表、属性面板、时间轴、底部工具栏和 3D 视窗。 |
| `src/domain` | 可复用的业务模型与计算：资产类型、时间轴关键帧采样、相机目标和输出画幅。 |
| `src/store` | Zustand 状态、编辑操作和时间轴写入。组件通过 store 发起业务操作。 |
| `src/three` | Three.js 场景对象、GLB / OBJ 加载、角色骨骼、相机和材质运行时。 |
| `src/export` | 快照和动画录制的导出封装。 |

## 数据流

```text
用户交互
  -> React 组件
  -> Zustand 编辑操作
  -> 项目状态 / 时间轴关键帧
  -> Three.js 运行时同步
  -> 3D 视窗与预览输出
```

## 时间轴约定

- 资产库与时间轴轨道分离：资产被插入时间轴后才生成轨道和默认关键帧。
- 时间轴保存资产在关键时刻的参数快照，不创建第二套资产。
- CTI 移动或播放时，`domain/animationTimeline.ts` 负责计算关键帧之间的状态，视窗实时应用结果。
- 角色位置关键帧可通过路径控制点形成二次贝塞尔曲线；路径切线用于计算角色朝向。

## 添加新能力的建议

1. 先在 `domain` 定义数据结构和纯计算规则。
2. 在 `store` 中增加可撤销、可复用的编辑操作。
3. 在 `components` 中接入用户交互和状态展示。
4. 最后在 `three` 中补充运行时可视化或场景同步。
